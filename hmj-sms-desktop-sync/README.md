# HMJ SMS Desktop Sync

Ultra-fast (< 250ms), serverless, end-to-end encrypted SMS notification and OTP sync between your Android phone and your desktop browser using standard VAPID Web Push (RFC 8291 / RFC 8292).

The extension pairs with the HMJ SMS Android app.

▶ [Watch the 43-second video on YouTube](https://www.youtube.com/watch?v=3L0DFOIFGVM)

## Supported Browsers

Google Chrome and Microsoft Edge, each on Windows, macOS, Linux, ChromeOS, GooglebookOS, and Android.

Firefox is not supported: messages arrive through Web Push, which needs a service worker, and Firefox gives extensions none.

## Features

* **Direct Serverless VAPID Web Push**: Android encrypts via RFC 8291 (`aes128gcm`) and signs with RFC 8292 ES256 JWT, dispatching directly to the browser's push service, such as Google FCM for Chrome. Zero middleman server required.
* **Instant Wakeup & Low Battery**: Chrome's Manifest V3 background service worker sleeps when idle and wakes up in milliseconds only upon receiving a push.
* **Zero Camera Permission QR Pairing**: Uses Google Play Services Code Scanner on Android to scan the high-contrast pairing QR code generated by the extension.
* **Desktop Notifications & 1-Click OTP Copy**: Incoming SMS messages trigger native desktop notifications with instant "Copy OTP" and "Copy Message" buttons. Clicking the notification itself copies the OTP, or the message when it has none.
* **Dual SIM Support**: Each message shows which SIM received it, such as `SIM 1` or `SIM 2: Jio` with the carrier name.
* **Keyboard, Screen Reader & Theme Support**: The popup and settings page work from the keyboard alone, announce copies and new messages to screen readers, and follow dark mode and high-contrast colours; the pairing QR code stays black on white so phones can read it.
* **Zero Cloud Storage / Complete Privacy**: Zero data stored on external servers or cloud databases. Messages exist only on your phone and local browser storage (auto-pruned after 24 hours).

## Setup Guide

### Step 1: Install the Extension

1. Open `chrome://extensions` (Chrome) or `edge://extensions` (Edge).
2. Enable **"Developer mode"**.
3. Click **"Load unpacked"** and select the `hmj-sms-desktop-sync/` directory.
4. Chrome and Edge keep a new extension's icon in their Extensions menu; pin it there to keep it on the toolbar.

Click the **HMJ SMS Desktop Sync** icon to view your pairing QR code. The gear in the popup opens the settings page, which shows the QR code too.

### Step 2: Pair with Android Phone

1. Open the **SMS** app on your phone.
2. Tap the top-right menu (3 dots) and choose **Desktop Sync**.
3. Tap **Scan QR Code** and scan the QR code displayed on your monitor.
4. Done! A test alert will pop up immediately on your desktop confirming the connection.

* `manifest.json`: the Chrome and Edge manifest. Runs `src/background.js` as the background service worker and requests the `offscreen` permission for clipboard writes.
* `src/sms-core.js`: the background code that does not need the service worker, so the tests can run it in a page: incoming messages, linked phones, the message feed and its pruning at install and startup, notification texts and what their clicks and buttons copy, and the messages from the popup and settings page.
* `src/background.js`: the Chrome and Edge service worker: Web Push subscription and pairing code, the push listener, notifications with copy actions (falling back to `chrome.notifications` with buttons), and clipboard copy through the offscreen document.
* `src/offscreen.html` and `src/offscreen.js`: the offscreen document that writes OTPs and messages to the clipboard for the service worker.
* `src/popup.html`, `src/popup.css` and `src/popup.js`: the toolbar popup with the pairing QR code and recent messages.
* `options/`: the settings and pairing page: connected devices, pairing QR code, test notification, and the message feed.
* `src/qrcode.js`: the QR code generator used by the popup and the options page.
* `store-assets/`: browser-store listing text and images. They are not included in the distribution packages.
* `tests/`: Playwright tests. `sms-core.spec.js` runs the background code through `src/background.js` against the fake APIs in `fake-chrome.js`, and `background.spec.js` covers the real Chrome service worker. `visual.spec.js-snapshots/` holds baseline screenshots of the popup and settings page; see [Screenshots](../README.md#screenshots) in the monorepo README.

## Permissions

* `notifications`: shows each incoming message, and the test notification, as a desktop notification.
* `clipboardWrite`: copies an OTP or a message when a notification or one of its buttons is clicked.
* `storage`: keeps the linked phones and recent messages locally in the browser.
* `offscreen`: opens the offscreen document that writes to the clipboard, since a service worker cannot.

## Privacy

The extension makes no network requests of its own, uses no analytics or tracking, and loads no remote code. Messages reach it from your phone through the browser's push service, encrypted for this browser alone, so the push service cannot read them.

Messages, the names of linked phones, and when each was last active are stored only in `chrome.storage.local`. What an open notification copies is held in `chrome.storage.session`, in memory only, until it is clicked or closed. Messages older than 24 hours are removed, and at most 100 messages and 10 phones are kept. **Clear Recent Messages** on the settings page removes all stored messages at once.

## Build

From the monorepo root, run:

```bash
./build.sh hmj-sms-desktop-sync
```

This writes Chrome and Edge ZIP files to `dist/`. For requirements and details about the shared build process, see the [monorepo README](../README.md#build).

## Known Limitations

* **Unlink** removes a phone from the list only. Every phone sends to the same push subscription, so a phone that is still paired can keep sending, and its next message lists it again.
