# HMJ SMS Desktop Sync

Ultra-fast (< 250ms), serverless, end-to-end encrypted SMS notification and OTP sync between your Android phone and your desktop browser using standard VAPID Web Push (RFC 8291 / RFC 8292).

The extension pairs with the HMJ SMS Android app.

## Supported Browsers

Google Chrome and Microsoft Edge, each on Windows, macOS, Linux, ChromeOS, GooglebookOS, and Android.

Firefox is not supported: messages arrive through Web Push, which needs a service worker, and Firefox gives extensions none.

## Features

* **Direct Serverless VAPID Web Push**: Android encrypts via RFC 8291 (`aes128gcm`) and signs with RFC 8292 ES256 JWT, dispatching directly to the browser's push service, such as Google FCM for Chrome. Zero middleman server required.
* **A VAPID Key of Its Own**: The extension makes its own P-256 VAPID key pair, subscribes to Web Push with it, and puts it in the pairing code (`sms_pair:v2`), so only phones that scanned this browser's code can push to it. No key is built into the app or the extension.
* **Several Phones**: Every phone scans the same QR code. Click a phone's name in the popup to list the linked phones and unlink one, or use **Unlink All Phones** in the popup's menu.
* **Instant Wakeup & Low Battery**: Chrome's Manifest V3 background service worker sleeps when idle and wakes up in milliseconds only upon receiving a push.
* **Zero Camera Permission QR Pairing**: Uses Google Play Services Code Scanner on Android to scan the high-contrast pairing QR code generated by the extension.
* **Desktop Notifications & 1-Click OTP Copy**: Incoming SMS messages trigger native desktop notifications with instant "Copy OTP" and "Copy Message" buttons. Clicking the notification itself copies the OTP, or the message when it has none. Only a notification with an OTP still to copy stays on screen until closed, and a new OTP closes the earlier notifications, so its Copy OTP button is never stacked out of sight.
* **Dual SIM Support**: Each message shows which SIM received it, such as `SIM 1` or `SIM 2: Jio` with the carrier name.
* **MMS and Group Messages**: An MMS is titled "New MMS from", or "Alice in group with Bob, Carol" for a group, with its subject before its text and a line such as `📷 2 photos · 🎬 Video`. This needs the HMJ SMS app to send the MMS fields (see [Pairing and Push Format](#pairing-and-push-format)); without them an MMS shows as its text.
* **Keyboard, Screen Reader & Theme Support**: The popup works from the keyboard alone, announces copies and new messages to screen readers, and follows dark mode, high-contrast colours and the system's request for more contrast; each time, such as `5m ago`, counts on while the popup is open and shows the full date and time when pointed at. The pairing QR code stays black on white, with every module a whole number of screen pixels, so phones can read it.
* **Translated**: All text, in the popup and in notifications, comes from `_locales/<language>/messages.json` in the browser's language: the 51 languages the Chrome Web Store supports besides English, which is the fallback. Plurals, numbers and lists follow the language's own rules, and right-to-left languages lay the popup out from the right. The path to the phone's QR scanner stays in English, as the HMJ SMS app shows it.
* **Zero Cloud Storage / Complete Privacy**: Zero data stored on external servers or cloud databases. Messages exist only on your phone and local browser storage (auto-pruned after 24 hours).

## Setup Guide

### Step 1: Install the Extension

1. Open `chrome://extensions` (Chrome) or `edge://extensions` (Edge).
2. Enable **"Developer mode"**.
3. Click **"Load unpacked"** and select the `hmj-sms-desktop-sync/` directory.
4. Chrome and Edge keep a new extension's icon in their Extensions menu; pin it there to keep it on the toolbar.

Click the **HMJ SMS Desktop Sync** icon to view your pairing QR code. **Copy Code** copies the same text, for the F-Droid build of the app, which pairs by pasting it. The code holds the keys to your link: show or paste it only on your own phone, and keep it away from clipboard sync and screen sharing.

### Step 2: Pair with Android Phone

1. Open the **SMS** app on your phone.
2. Tap the top-right menu (3 dots) and choose **Desktop Sync**.
3. Tap **Scan QR Code** and scan the QR code displayed on your monitor.
4. Done! A test alert will pop up immediately on your desktop confirming the connection.

### Unlinking

* **One phone**: click the phone's name under the popup's toolbar and choose **Unlink**. Its messages are ignored from then on, and a quiet notice, replaced in place, counts the ones it still sends; clicking it opens the popup. Every phone shares one push address, so to stop that phone sending, also unlink this computer in the SMS app on it. Pairing it again, which sends a test alert, links it again.
* **All phones**: **Unlink All Phones** in the popup's menu (⋮) ends the push subscription, makes a new key and pairing code, and removes all stored messages. No phone can reach the browser any more, and each one removes the link itself on its next send. The phones you keep must scan the new QR code.

### Pairing Again

The browser can end the push subscription on its own, such as after months without a message, when its notifications are blocked, or when its profile is repaired; the phones then cannot reach it and remove the link themselves. The extension checks at browser startup, when the popup opens, and before each pairing code. When the subscription is gone or replaced, it clears the list of phones and the popup asks you to scan the QR code again on each phone, until one does. Another notice in the popup says when the browser has turned off the extension's notifications, as messages are then stored but not shown.

## Pairing and Push Format

The QR code holds `sms_pair:v2|<endpoint>|<p256dh>|<auth>|<vapidPublic>|<vapidPrivate>|<name>`: the push subscription's endpoint and keys, the VAPID key pair (65-byte public point, 32-byte private scalar, base64url without padding), and a name such as `Chrome (ChromeOS)` or `Edge (Windows)`. It is at most 2048 characters.

Each push is the JSON `{id, sender, body, timestamp, otp, deviceId, deviceName, simSlot?, simName?}`, or `{type: "TEST_PING", message, deviceId, deviceName}` when the phone pairs. An MMS adds `kind: "mms"` and may add `subject`, `attachments` (each `image`, `video`, `audio`, `contact` or `file`) and `group` (the other members' names); these count only with `kind: "mms"`.

```text
    ├── locales.spec.js

    ├── popup.spec.js
    ├── qrcode.spec.js
    ├── sms-core.spec.js
    ├── visual.spec.js
    └── visual.spec.js-snapshots/
```

* `manifest.json`: the Chrome and Edge manifest. Runs `src/background.js` as the background service worker and requests the `offscreen` permission for clipboard writes.
* `src/sms-core.js`: the background code that does not need the service worker, so the tests can run it in a page: incoming messages, linked and unlinked phones, the VAPID key, push subscription and pairing code, Unlink All, the message feed and its pruning at install and startup, notifications and what their clicks and buttons do, and the messages from the popup.
* `src/message-format.js`: how a message reads in a notification and in the popup: its title, its text with the MMS subject, and its attachment line.
* `src/i18n.js`: the text in the browser's language for the popup and the background: `t()` for a message, `plural()` for one that counts (`name_one`, `name_other`, and the language's other plural forms), lists, and `localizePage()`, which fills the popup's `data-i18n` elements. To add a language, add `_locales/<language>/messages.json` with the English file's names; `locales.spec.js` keeps the code, the English messages and the popup's English HTML in step.
* `src/background.js`: the Chrome and Edge service worker: the browser's name, its PushManager, the push listener, notifications with copy actions (falling back to `chrome.notifications` with buttons), and clipboard copy through the offscreen document.
* `src/offscreen.html` and `src/offscreen.js`: the offscreen document that writes OTPs and messages to the clipboard for the service worker.
* `src/popup.html`, `src/popup.css` and `src/popup.js`: the toolbar popup: the pairing QR code, the linked phones with Unlink, the menu with Unlink All Phones and Clear Messages, and recent messages.
* `src/qrcode.js`: the QR code generator used by the popup.
* `store-assets/`: browser-store listing text and images. They are not included in the distribution packages.
* `tests/`: Playwright tests. `sms-core.spec.js` runs the background code through `src/background.js` against the fake APIs in `fake-chrome.js`, and `background.spec.js` covers the real Chrome service worker, with a fake `PushManager` that behaves like Chrome's, as headless Chromium has no push service. `visual.spec.js-snapshots/` holds baseline screenshots of the popup; see [Screenshots](../README.md#screenshots) in the monorepo README.

## Permissions

* `notifications`: shows each incoming message, and the notice about an unlinked phone, as a desktop notification.
* `clipboardWrite`: copies an OTP or a message when a notification or one of its buttons is clicked.
* `storage`: keeps the linked phones and recent messages locally in the browser.
* `offscreen`: opens the offscreen document that writes to the clipboard, since a service worker cannot.

## Privacy

The extension makes no network requests of its own, uses no analytics or tracking, and loads no remote code. Messages reach it from your phone through the browser's push service, encrypted for this browser alone, so the push service cannot read them.

Messages, the names of linked and unlinked phones, when each was last active, the VAPID key pair, and the push address the phones were given are stored only in `chrome.storage.local`. The private key is not encrypted there; it only lets a holder push to this browser, it reads nothing, and **Unlink All Phones** replaces it. What an open notification copies is held in `chrome.storage.session`, in memory only, until it is clicked or closed. Messages older than 24 hours are removed, and at most 100 messages, 10 linked phones and 20 unlinked phones are kept. **Clear Messages** in the popup's menu removes all stored messages at once, and so does **Unlink All Phones**.

## Build

From the monorepo root, run:

```bash
./build.sh hmj-sms-desktop-sync
```

This writes Chrome and Edge ZIP files to `dist/`. For requirements and details about the shared build process, see the [monorepo README](../README.md#build).

## Known Limitations

* **Unlink** for one phone only ignores its messages. Every phone sends to the same push subscription with the same key, so only the phone itself, or **Unlink All Phones**, can stop it sending. A phone could also send as another, which matters only if you pair phones you do not trust.
